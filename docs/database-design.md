# Database Design - PlateMate

## Overview

PlateMate is an AI-powered food redistribution platform that connects food providers with food receivers to reduce food waste and improve food accessibility.

The database is designed around six core entities:

1. User
2. Organization
3. Food Listing
4. Food Request
5. Match
6. Delivery

---

# 1. User

Represents any person who can access the platform.

## Purpose

* Authentication
* Authorization
* Platform access

## Attributes

| Field      | Description                |
| ---------- | -------------------------- |
| id         | Unique identifier          |
| name       | Full name                  |
| email      | User email                 |
| password   | Encrypted password         |
| role       | PROVIDER, RECEIVER, ADMIN  |
| created_at | Account creation timestamp |

## Relationships

* One User may belong to one Organization.
* One User has one Role.

---

# 2. Organization

Represents a provider or receiver organization.

Examples:

* Restaurant
* Bakery
* Hotel
* Supermarket
* Wedding Venue
* NGO
* Shelter Home
* Orphanage
* Food Bank
* Individual

## Purpose

Stores organization-specific information.

## Attributes

| Field      | Description           |
| ---------- | --------------------- |
| id         | Unique identifier     |
| user_id    | Associated user       |
| name       | Organization name     |
| type       | Organization category |
| phone      | Contact number        |
| address    | Address               |
| latitude   | Geographic latitude   |
| longitude  | Geographic longitude  |
| verified   | Verification status   |
| created_at | Creation timestamp    |

## Organization Types

* RESTAURANT
* BAKERY
* HOTEL
* SUPERMARKET
* WEDDING_VENUE
* CORPORATE_CAFETERIA
* COLLEGE_MESS
* NGO
* SHELTER_HOME
* ORPHANAGE
* FOOD_BANK
* COMMUNITY_KITCHEN
* INDIVIDUAL

## Relationships

* One Organization belongs to one User.
* One Organization can create many Food Listings.
* One Organization can create many Food Requests.

---

# 3. Food Listing

Represents surplus food available for donation.

## Purpose

Allows providers to publish available food.

## Attributes

| Field         | Description                 |
| ------------- | --------------------------- |
| id            | Unique identifier           |
| provider_id   | Organization providing food |
| food_name     | Name of food item           |
| food_category | Category of food            |
| quantity      | Available quantity          |
| unit          | Meals, kg, packets, etc.    |
| prepared_at   | Preparation time            |
| expiry_at     | Expiry time                 |
| description   | Additional details          |
| status        | Current status              |
| created_at    | Creation timestamp          |

## Status Values

* AVAILABLE
* MATCHED
* PICKED_UP
* DELIVERED
* EXPIRED

## Relationships

* One Food Listing belongs to one Organization.
* One Food Listing can be matched to multiple Food Requests.

---

# 4. Food Request

Represents food demand from receivers.

## Purpose

Allows receivers to request food.

## Attributes

| Field           | Description             |
| --------------- | ----------------------- |
| id              | Unique identifier       |
| receiver_id     | Requesting organization |
| food_category   | Required food category  |
| quantity_needed | Quantity required       |
| required_before | Deadline                |
| status          | Request status          |
| created_at      | Creation timestamp      |

## Status Values

* PENDING
* PARTIALLY_FULFILLED
* FULFILLED
* CANCELLED

## Relationships

* One Food Request belongs to one Organization.
* One Food Request can receive food from multiple Food Listings.

---

# 5. Match

Represents allocation between a Food Listing and a Food Request.

## Purpose

Stores matching results generated by the system.

## Attributes

| Field              | Description            |
| ------------------ | ---------------------- |
| id                 | Unique identifier      |
| listing_id         | Food Listing reference |
| request_id         | Food Request reference |
| allocated_quantity | Allocated quantity     |
| status             | Match status           |
| matched_at         | Matching timestamp     |

## Status Values

* PROPOSED
* ACCEPTED
* REJECTED
* COMPLETED

## Relationships

* One Match belongs to one Food Listing.
* One Match belongs to one Food Request.
* One Match can have one Delivery.

---

# 6. Delivery

Represents transportation of food from provider to receiver.

## Purpose

Tracks food movement.

## Attributes

| Field         | Description        |
| ------------- | ------------------ |
| id            | Unique identifier  |
| match_id      | Associated match   |
| pickup_time   | Pickup timestamp   |
| delivery_time | Delivery timestamp |
| driver_name   | Delivery person    |
| status        | Delivery status    |

## Status Values

* PENDING
* PICKED_UP
* IN_TRANSIT
* DELIVERED
* FAILED

## Relationships

* One Delivery belongs to one Match.

---

# Entity Relationships Summary

User
→ Organization

Organization
→ Food Listing

Organization
→ Food Request

Food Listing
→ Match

Food Request
→ Match

Match
→ Delivery

This structure provides the foundation for surplus prediction, demand forecasting, route optimization, food redistribution, and future digital twin capabilities.
